# sluiceULPmax

Поиск по текстовым базам одним проходом: любое число запросов, скорость ограничена
только диском. Rust, открытый исходный код, MIT.

```
  3.27 ГБ и 132 запроса           →  8.4 секунды  (417 МБ/с, обычный SATA SSD)
  чтение того же файла без поиска →  9.1 секунды
```

## Скачать и запустить

**[→ Последняя версия (Releases)](../../releases/latest)** — там лежат готовые файлы под
все три платформы. Собираются автоматически на GitHub Actions, в самом репозитории
бинарников нет: так они не устаревают и не тянут лишнее в историю.

| система | файл из Releases | как запустить |
|---|---|---|
| **Windows 10/11 x64** | `sluiceULPmax-windows-x64.exe` | скачать и дважды кликнуть. Ставить ничего не нужно |
| **Linux x64** | `sluiceULPmax-linux-x64` | `chmod +x sluiceULPmax-linux-x64`<br>`./sluiceULPmax-linux-x64` |
| **macOS (Apple Silicon)** | `sluiceULPmax-macos-arm64` | `chmod +x sluiceULPmax-macos-arm64`<br>`./sluiceULPmax-macos-arm64` |
| **из исходников** | — | `cargo build --release`, бинарник в `target/release/` |

Если macOS ругается на неизвестного разработчика:

```bash
xattr -d com.apple.quarantine sluiceULPmax-macos-arm64
```

На Linux и macOS можно не качать бинарник, а запустить скриптом — он найдёт готовый
файл рядом или соберёт проект сам:

```bash
./run.sh
```

## Как пользоваться

Запуск без аргументов открывает мастер:

```
источники → запросы → вывод → прогон → итоги
```

1. **источники** — `[+ файл]`, `[+ папка]` открывают проводник; можно перетащить файл
   в окно терминала или вставить путь.
2. **запросы** — через `|` или построчно; `Ctrl+V` работает, кириллица тоже.
3. **вывод** — `url:login:pass`, `login:pass` или только счётчики; папка выбирается
   тем же проводником.
4. **прогон** — полоса прогресса, скорость и живая таблица лидеров.
5. **итоги** — запрос и сколько нашлось, плюс куда легли файлы.

| клавиша | действие |
|---|---|
| `Tab` / `←→` | перевести фокус по кнопкам |
| `Enter` | нажать кнопку в фокусе |
| `↑↓` | выбор в списке |
| `Esc` | назад / прервать прогон |
| `Ctrl+V` | вставить из буфера |
| `Q` / `Ctrl+C` | выход |

Мышь работает: клик по кнопке, по строке списка, по строке файлового браузера.

## Потоки

Сколько потоков нужно, зависит не от числа ядер, а от скорости диска: `диск / (скорость одного потока × 0.8)`.

По умолчанию — `авто`: программа замеряет диск и скорость сканера на первых 32 МБ и считает сама.
На быстрых носителях разрешена переподписка до двух раз от числа ядер: лишние потоки прячут
задержки ввода-вывода.

Меняется в двух местах:

- **в интерфейсе** — экран «вывод», строка `потоки`: кнопка `[потоки]` или клавиши `+` / `-`;
  значения: авто, 2, 4, 8, 12, 16, 24, 32;
- **в командной строке** — `--threads N` или `--threads auto`.

Ориентир: на SATA SSD (~400 МБ/с) хватает 4 потоков, на NVMe (~5 ГБ/с) — 16 и больше,
на HDD (~80 МБ/с) — 2. Проверить своё железо: `--caps` покажет замер и рекомендацию.

## Командная строка

```bash
sluiceULPmax <файл|папка> "q1|q2" --count
sluiceULPmax <файл> --file списки.txt --format login --out hits
sluiceULPmax <файл> --file patterns.txt --caps
sluiceULPmax <файл> --bench io
sluiceULPmax <файл> --file patterns.txt --bench scan
```

| ключ | что делает |
|---|---|
| `--count` | только посчитать, строки не писать |
| `--tsv` | `count<TAB>pattern`, удобно для сверок |
| `--format url\|login\|raw` | вид выходной строки |
| `--out <папка>` | куда писать (по умолчанию `hits`) |
| `--threads auto\|N` | потоки (по умолчанию auto: замер диска и подбор) |
| `--chunk МБ` | буфер на поток (по умолчанию 32) |
| `--engine filter\|ac` | движок поиска (по умолчанию filter) |
| `--caps` | диагностика: ядра, скорость диска, рекомендация |
| `--bench io\|cpu:N\|scan` | замеры: диск / процессор / полный проход |
| `--no-ci` | учитывать регистр |
| `-V` | версия |

## Как это работает

1. файл режется на N блоков, границы выровнены по переводу строки — потоки не пересекаются;
2. каждый поток читает свой диапазон через `pread`, файл открыт с `FILE_FLAG_SEQUENTIAL_SCAN`;
3. фильтр по парам байт: таблица 64 КиБ живёт в L2, кандидаты — через CSR-список;
4. хвост недописанной строки переносится в следующий буфер — на швах ничего не теряется;
5. интерфейс — отдельный поток, счётчики в атомиках, перерисовка раз в 70 мс.

## Ограничения

- литералы, без регулярок — осознанно, регулярки убили бы скорость;
- поиск по подстроке: запрос `site` поймает и `mysite`;
- готовые сборки: Windows x64, Linux x64, macOS arm64.
